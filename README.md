# VetAssist AI

An Intelligent Career and Rehabilitation Support System for Veterans.

VetAssist AI is a retrieval-augmented agent that answers veteran employment pathway questions. It combines a local corpus of vocational rehabilitation literature, live PubMed, web and O*NET lookups, and privacy-protected statistics from RSA-911 administrative data. The repository also contains the evaluation pipeline used to compare agent models against general-purpose baselines.

## What Is in This Repository

- Code for the agent, web app, RSA-911 privacy tooling, and evaluation.
- The public corpus: `_raw/`, `_processed/`, `docs_text/`, `chunks.jsonl`, `manifest.csv`, `sources.txt`.
- The Chroma index `chroma_db_adv/` (stored with Git LFS).
- Benchmarks: `eval_benchmark.json`, `eval_benchmark_full_system.json`, `eval_benchmark_expanded.json`.

Not included: private RSA-911 data and anything derived from it (`data/rsa911_private/`), saved evaluation runs (`statistics/runs/`, `statistics/current_evaluation/`, `statistics/comparison/runs/`), logs, and `.env`. Run outputs are regenerated by running the evaluation.

## Setup

```bash
git lfs pull
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
cp .env.example .env   # then fill in the keys
```

### Model Provider

The agent uses Groq by default (`GROQ_API_KEY`). To run a local model through Ollama instead, set in `.env`:

```bash
AGNO_MODEL_PROVIDER=ollama
OLLAMA_MODEL=qwen3.8:27b   # default
OLLAMA_HOST=               # optional, defaults to the local Ollama server
```

RSA-911 tools are enabled only when the model runs locally through Ollama, so no RSA-911 output is sent to a hosted model.

| File | Purpose |
| --- | --- |
| `pathways_agent.py` | Main Agno agent: tool definitions, citation handling, and grounded answer synthesis |
| `app_web.py` | FastAPI chat web UI with login and PDF export; page files are in `web/` |

Run the web UI locally at http://127.0.0.1:7860 (requires `APP_USERNAME` and `APP_PASSWORD` in `.env`):

```bash
.venv/bin/python app_web.py
```

Run the web UI with a public Cloudflare URL (needs `cloudflared` in `~/bin`). Do not do this while RSA-911 tools are enabled; `rsa911/secure.sh check` flags a running tunnel.

```bash
./run_public.sh
```

Run the command-line agent:

```bash
.venv/bin/python pathways_agent.py
```

## RSA-911 Privacy Tooling (`rsa911/`)

RSA-911 is private administrative data. Raw files stay outside the project, derived files are written to `data/rsa911_private/`, and only aggregate results with at least 11 people per cell ever leave the database.

| Module | Purpose |
| --- | --- |
| `inspect_schema.py` | Writes file names, headers, and column counts; prints no rows |
| `convert_xlsx.py` | Converts an RSA-911 Excel export to CSV; prints counts only |
| `build_sqlite.py` | Builds the local SQLite database from the private CSVs |
| `private_aggregate.py` | Aggregate veteran outcome summaries with small-cell suppression |
| `analysis.py` | Disparity comparisons and predictor model summaries |
| `statistical_analysis.py` | Descriptive statistics, feature importance, and associations |
| `safe_sql.py` | Validates and runs one aggregate SQL query (`n >= 11`, allowlisted columns, no row-level output) |
| `dp.py` | Differential privacy (OpenDP discrete Laplace) for the agent's SQL queries, with a lifetime epsilon budget |
| `privacy_attacks.py` | Empirical attacks against the SQL tool to measure what an attacker could learn |
| `build_ground_truth.py` | Fills in RSA-911 ground truth for the expanded benchmark; output stays in `data/rsa911_private/` |
| `code_labels.py` | Labels for RSA-911 codes |
| `secure.sh` | Locks down permissions, installs git guards, audits data exits, and encrypts raw CSVs |

Pipeline:

```bash
.venv/bin/python -m rsa911.inspect_schema --count-rows
.venv/bin/python -m rsa911.build_sqlite --replace
.venv/bin/python -m rsa911.private_aggregate --min-cell-size 11
.venv/bin/python -m rsa911.analysis --min-cell-size 11
.venv/bin/python -m rsa911.statistical_analysis --min-cell-size 11 --top-n 20
.venv/bin/python -m rsa911.build_ground_truth
```

How the agent queries the data:

1. For a dataset question, the agent reads the allowed schema and writes one aggregate SQL query.
2. `safe_sql.py` parses and validates it: one flat `SELECT` over `rsa911_exiters`, allowlisted columns only, `COUNT(*) AS n` required, no subqueries, joins, `MIN`/`MAX`, or `SELECT *`.
3. Rows with `n < 11` are dropped and small counts and rates are suppressed.
4. `dp.py` adds calibrated noise before the result reaches the agent, so two allowed queries cannot be subtracted to reveal one person. Repeating an identical query returns the saved answer and spends no budget.

Differential privacy settings (in `.env`): `RSA911_DP=on|off`, `RSA911_DP_EPSILON` (default 1.0), `RSA911_DP_DELTA` (default 1e-6), `RSA911_DP_BUDGET` (default 50). Check the remaining budget with `.venv/bin/python -m rsa911.dp`.

Privacy rules: never commit raw CSVs or `data/rsa911_private/`, never paste row-level data anywhere, and share only aggregate outputs with small-cell suppression.

## Evaluation

`evaluate_agent.py` runs the benchmark, RAGAS, LLM judge, human review sheet, agreement, and report steps:

```bash
.venv/bin/python evaluate_agent.py run-benchmark --benchmark eval_benchmark_full_system.json
.venv/bin/python evaluate_agent.py prepare --runs statistics/current_evaluation/benchmark_runs.json --benchmark eval_benchmark_full_system.json
.venv/bin/python evaluate_agent.py ragas
.venv/bin/python evaluate_agent.py judge
.venv/bin/python evaluate_agent.py human-sheet
.venv/bin/python evaluate_agent.py agreement
.venv/bin/python evaluate_agent.py report
```

`prepare` reads the `benchmark_runs.json` written by `run-benchmark`, so run that first.

### Model Comparison

`run_experiment.sh` runs the full comparison locally through Ollama, one model at a time: each agent model answers the expanded benchmark, then the judge scores the run (rubric, fact check, correctness), RAGAS runs on the retrieved evidence, and a report is written. Failed questions and steps are retried, and rerunning the script resumes where it stopped.

- Agent models: `gpt-oss:20b`, `qwen3.8:27b`, `mistral-small3.2:24b`
- Judge model: `llama3.3:70b`
- Requires the private benchmark built by `rsa911.build_ground_truth`
- Results go to `statistics/runs/<RUN_TAG>_<model>/`

```bash
ollama pull gpt-oss:20b && ollama pull qwen3.8:27b && ollama pull mistral-small3.2:24b && ollama pull llama3.3:70b
bash run_experiment.sh
```
